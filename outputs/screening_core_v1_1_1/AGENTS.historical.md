# 澳大利亚海外小商户首单验证｜项目规则

当前筛选权威版本：`Screening Core v1.1.1`。产品价格与范围、筛选、评分、辅助标签、Track、Prospect Source 与 Demo Scope 的详细定义只在 [PROJECT_CORE.md](PROJECT_CORE.md) 维护；当前首封模板、CTA、邮件个性化、邮件 QA 与 Current Offer 只在 [OUTREACH_EMAIL_SOP.md](OUTREACH_EMAIL_SOP.md) 维护。历史/Deprecated 内容不得覆盖 Current Authority。

## 项目身份

- 目标：验证澳大利亚海外小商户的首个 **AU$800** 纯静态单页网站订单。
- 进入本项目的会话，在进行 prospecting、客户分析、Demo 准备、邮件/IG 文案、外联规划或交付前，必须先完整读取同目录 [PROJECT_CORE.md](PROJECT_CORE.md)。
- PMO 只治理、派单与验收；具体研究、制作与验证由独立 Owner 完成。

## 产品硬门槛

- 仅静态 HTML/CSS/少量前端 JS；无 CMS、后台、数据库、登录、自建预约、电商、支付、库存或服务端表单。
- 第三方预约仅可外链；我方不登录、不维护第三方系统，也不承担持续内容更新。
- 所有 Demo 制作或准备会话必须先完整读取并遵守 [PROJECT_CORE.md](PROJECT_CORE.md) 中的权威 `Demo Production v1.0`；用户授权制作不等于客户素材授权，也不自动授权发送、公开发布或生产上线。
- `Client-showable Demo` 是 Cold Outreach 中可直接让客户打开、截图和展示的完成品级钩子，不是内部原型、wireframe、草稿或半成品。`内容 35–50%` 只表示选择核心业务切片，不表示页面完成 35–50%；实际展示的 Hero、价值点、2–3 项服务、信任信息、CTA 及移动端必须达到 100% 完成度。
- Demo 禁止占位符、TODO、空白或残缺区块、临时/默认文案、临时图片、死链、假表单、未完成导航、内部说明或“以后再补”的可见痕迹。`Shown in Demo / Reserved for Final Delivery` 只区分范围；Reserved 可不展示，但不得以故意降质、留 Bug 或残缺制造正式交付增量。
- Desktop 与约 390px 必须同时达到可直接发送的视觉、内容和交互完成度；任一不满足固定标记 `CLIENT-SHOWABLE DEMO = FAIL`，不得进入截图、邮件或外联准备。整体方向、信息架构、素材质量或视觉完成度不达标时必须整体重做，不得用零散 P2 修补掩盖根本失败；此门禁不改变客户素材授权、Demo 制作授权、部署或发送授权边界。
- Demo 会话还必须遵守 [PROJECT_CORE.md](PROJECT_CORE.md) `Demo Production v1.0` 的 `Bottom 40% Commercial Architecture` 与独立 QA Gate；这是一组按行业事实选择的收尾策略，不是新的固定页面模板。未发送 Demo 未通过时不得进入外联准备。
- Cold Demo 目标制作时间仍为 30–60 分钟，并必须记录 `Actual Demo Minutes`；连续多个 Demo 明显超时触发 `SOP Cost Review`。时间目标不得削弱 Business Fidelity、Desktop/约390px QA、CTA、图片、Bottom 40% 或精修质量。`Polished Cold Demo ≠ Finished Production Website`。
- Demo 与每封待发送邮件都必须通过权威 `CLIENT-VISIBLE INTERNAL-TEXT GATE`：Demo 细则见 [PROJECT_CORE.md](PROJECT_CORE.md) 14.4A，邮件发送前细则见 [OUTREACH_EMAIL_SOP.md](OUTREACH_EMAIL_SOP.md)。新内容与未发送草稿立即适用；已发送内容不追溯，重用、重新截图或再次外联时重验。该 Gate 不构成发送授权。

## Prospect 硬门槛

- 所有 prospecting / 筛选会话第一步必须先按 [PROJECT_CORE.md](PROJECT_CORE.md) 执行 `H0 / Gate 0 — Current Trading Status`。H0 只验证商户目前是否仍在真实经营；近 90 天、身份可交叉确认的可信公开客户评价可以独立通过 H0，不要求老板本人发社媒或官网更新。H0 不证明 Growth Intent、Website Need、Purchase Intent、Digital Sophistication 或 AU$800 支付意愿。
- H0 PASS 后必须先完成网站状态与互斥通道分类，再执行 `H0.5 / Gate 1 — Meaningful Demo Opportunity`。H0.5 只做 `PASS / FAIL` 资格判断，不再维护35分二次模型；升级机会强弱只由 `Website Opportunity — 30` 排序。访问或归属不足保持对应 `BLOCKED/HOLD`，不得猜测 PASS。
- 当前经营、独立或本地可决策；属于“好生意 + 无独立网站或差展示”。阶段性发现投入目标为 Track N 约 60%、Track W 约 40%，不得为凑比例降低任何硬门槛。
- Track N 与 Track W 均必须按照 [PROJECT_CORE.md](PROJECT_CORE.md) 完成 `Meaningful Demo Opportunity`、Evidence-backed Business Health、Single-page Fit、Purchase Signal 与 Public Business Email Gate。`AGENTS.md` 不另外设置网站问题数量、展示缺口数量或商业信号数量门槛；这不取消 100 分模型及其现有分项最低线。
- 联系方式硬门固定为 `Public Business Email: PASS / FAIL`。只有来源可复核的公开业务邮箱可通过；电话、Contact Form、Instagram、Facebook、Messenger、WhatsApp 均不得替代或给 Contact Viability 加分。邮箱可用性与决策者触达分别按 [PROJECT_CORE.md](PROJECT_CORE.md) 记录；公开邮箱不等于合规或发送授权。
- 所有筛选会话必须使用 [PROJECT_CORE.md](PROJECT_CORE.md) 中 `Screening Core v1.1.1` 的权威 `Prioritisation Score`，并在候选记录中填写 `Track`、`Website Status` 与 `Website Status Evidence`；评分只排序已通过 H0、Track Classification、对应 H0.5 且已核验证据的商户，不得覆盖 H0、H0.5 或 H1–H6 硬门槛，也不构成 Demo、外联或发送授权。
- 100 分固定定义为 `Prioritisation Score`，不是购买或成交概率。辅助标签 `Website Relevance to Customer Acquisition`、`Growth Intent Evidence`、`Industry Economic Leverage`、`Business-specific Website Leverage` 不得成为隐藏分数；无公开证据时按规则写 `UNKNOWN`。
- Prospect Source 必须按行业选择并记录类型与 URL；Google Maps 只是可选来源之一，不得作为所有行业的统一主来源。Track N/W 的 60/40 只是 discovery preference，必须记录目标比例、实际合格比例与偏差原因，不得操纵结果。

## 外联与隐私边界

- 所有 Cold Outreach 首封邮件起草会话必须先完整读取并遵守同目录 [OUTREACH_EMAIL_SOP.md](OUTREACH_EMAIL_SOP.md)；不得自由发明首封结构。该 SOP 只规范草稿，不构成发送或合规授权。
- 免费源码实验当前固定为 `DEPRECATED — EXPERIMENT NOT ACTIVE`。首封不得承诺免费 HTML/CSS/JavaScript 或完整 source files；未获用户后续明确授权不得恢复该实验。
- 邮件/IG 私信模板或草稿不等于发送授权。真实外联、登录、提交、部署、付费，均须当前用户对具体目标明确授权。
- 公开邮箱不等于营销同意：逐家记录来源、日期、业务相关性、拒收声明或同意依据；不推测私人邮箱、不批量群发。
- 邮件中的 Demo 链接必须真实、可访问、可点击，并按实际访问状态准确描述；公网但不主动列出的页面只能称 `unlisted concept preview` 或 `independent concept`，不得称 private。HTML 邮件截图只能作预览，不得加入追踪像素、UTM 或任何收件人行为追踪。
- 身份和联系方式仅可在已授权的商户外联或用户要求的签名中使用；不得用于其他项目、公开 Demo、代码、日志或公开发布。

## 客户会话最终回报

- 客户研究、Demo 准备或外联准备会话在最终回 PMO 前，必须先完整读取 [PROJECT_CORE.md](PROJECT_CORE.md)，并按其中 `OUTREACH DRAFT PACKAGE` 契约直接整理收件邮箱证据、个性化主题、纯文本与 HTML 正文、Demo 链接/截图、合规状态、授权状态和阻断项。
- 无可靠邮箱写 `NOT VERIFIED`；无实际 Demo 或截图写 `NOT READY`，不得猜测或假称已完成。
- 整理邮件包仅是草稿交付，不等于发送授权；默认状态固定为 `DRAFT ONLY — NOT AUTHORIZED TO SEND`。

产品价格、产品范围、Screening、Demo 与排除项见 [PROJECT_CORE.md](PROJECT_CORE.md)；当前邮件模板、CTA、邮件 QA 与 Offer 规则见 [OUTREACH_EMAIL_SOP.md](OUTREACH_EMAIL_SOP.md)。
