# Cold Outreach Email SOP｜首封权威规则

本文件是本项目所有 Cold Outreach 首封邮件的唯一权威结构。它只规范草稿，不是发送、登录邮箱、部署或澳大利亚外联合规授权。产品价格仍为 AU$800；“首封不报价”不改变产品定价。

## 1. 唯一目标与固定逻辑

首封唯一目标：让真实商户老板打开为其定制的 Demo，并愿意回复。首封不是成交、报价、网站审计、合同说明或设计反馈请求。

固定顺序不得自由改造：

`Research → Personal observation → Already made specifically for the business → Demo URL → No changes made → No-pressure source-file gift → Optional offer to finish it → Simple reply CTA`

核心表达：`Rather than sending a generic web design pitch, I put together a small website concept specifically for [Business Name].`

## 2. 内容规则

- 100–160 个英文单词；自然、简单、低压。
- 第一段必须使用已有 evidence，写地点、业务类型、具体服务、目标客户或可验证经营特点；不得编造或空泛赞美。
- Demo 必须明确是 `specifically for [Business Name]`，不能只写 “I made a website concept.”
- 用老板能理解的 Business Outcome：`make your services easier to understand`、`make enquiries easier to begin`、`give visitors a clearer path to request a quote`、`make your main services easier to browse on mobile`、`make phone/email contact easier to find`。禁止 UX、information architecture、conversion funnel 等内部术语。
- 内部可以记录网站问题；首封默认只中性描述另一种更清楚的呈现方案。
- CTA 先提供无压力价值：`If you like the direction, just reply to this email. I’d be happy to send you the demo’s HTML, CSS and JavaScript source files at no charge, with no obligation to hire me.` 如需保留成交路径，再简短补充：`If you’d prefer me to finish and tailor it for [Business Name], I can help with that too.` 不索取设计反馈，不要求开会。
- 必须包含可执行退订：`If you’d prefer not to hear from me again, reply “unsubscribe” and I won’t contact you again.`

### 2A. 免费 Demo 源码承诺

- 首封只承诺客户回复后可免费取得当前 Demo 的可转让源码，不在首封附 ZIP、附件或下载链接，也不暗示客户必须购买、开会或提供反馈。
- `source files` 固定指我方可合法转让的当前 Demo HTML、CSS、JavaScript，以及已明确可转让的随包素材；不得承诺第三方受限图片/字体、客户未授权素材、账户、凭证、托管权限、后台、数据库、付费依赖或持续支持。
- 加入源码承诺前，内部必须确认 `SOURCE GIFT ELIGIBLE = YES`：代码归属清楚、没有秘密、客户可见内部文字 Gate 通过、素材许可允许转让、源码包不含追踪或收件人标识。任一项为 `NO / UNKNOWN` 时，删除源码赠送句，不得模糊承诺。
- 免费源码按当前 Demo 状态原样提供，不自动包含正式上线、客户内容核实、完整响应式 QA、浏览器兼容、持续维护或生产支持；这些差异用于内部范围管理，不在首封堆叠免责声明。
- 客户回复索取源码后，实际整理、上传或发送源码仍是新的外写动作，必须由当前用户针对该客户明确授权，并在发送前重新执行文件、素材、秘密与内部文字检查。

## 3. 禁止项

首封默认禁止（固定检查标记：`NO AU$800 IN FIRST EMAIL`）：

- 批评客户网站，例如 `outdated`、`confusing`、`poor`、`difficult`、`visitors struggle`、`too many competing details`、`needs improvement`、`old`、`not converting`；仅在客观技术故障已核验且当前用户明确授权时例外。
- 写 AU$800、$800、50% deposit、one-time price、合同条款、ROI 承诺、开会请求或设计反馈型 CTA。
- 长篇自我介绍、虚假紧迫感、无法证实结果或暗示已与商户合作。
- URL shortener、跟踪重定向、UTM、识别性参数、陌生下载链接；默认不得要求登录或密码，除非项目对具体方式明确授权。

客户主动询问价格后才进入 `Pricing Reply`。只有当前用户对具体商户的具体首封明确要求报价，才可例外；产品本身仍按 PROJECT_CORE 执行。

## 4. Demo 状态与链接

- 链接必须真实、可访问，并放在固定文字 `You can view it here:` 之后。
- 只有 access-controlled Demo 才能称 `private`。
- 公网可访问但不主动列出的 Demo 统一称 `unlisted concept preview` 或 `independent concept`；禁止称 `private`、`unpublished`、`not published`。
- 必须保留：`I haven’t made any changes to your current website — this is simply an independent concept for you to look at.`
- Demo 不存在、链接不可访问、状态未核验或素材/合规 Gate 未通过时，标记 `NOT READY`，只可起草，不得发送。

### 4A. 最终链接、截图与收件地址路径核验

触发条件：准备发送、替换 Demo URL/截图/收件地址，或公开页面可见地址与 `mailto:`、目录或既有研究记录不一致。

- **必须动作**：从最终待发送的纯文本和 HTML 中逐一取出 Demo 裸 URL、文字链接、截图外层链接及收件地址；在无登录/无既有会话依赖的真实浏览器中打开每个 Demo 链接，并对照最终截图和页面访问状态。收件地址只可采用有来源、日期和业务相关性的公开商业地址；若同一客户的可见地址与 `mailto:` 或其他公开来源冲突，先保留为 `NOT VERIFIED`，不得猜测或以 MX 代替收件人存在性。
- **可复核证据**：内部记录最终 URL 的解析后地址、访问状态、截图生成时间/对应最终页面，以及收件地址的 Source URL、retrieved date、原样地址和冲突处理结论；不在客户邮件、截图或 Demo 中展示这些治理字段。
- **FAIL 状态**：任一 Demo 入口不能打开、链接目标与裸 URL/截图链接不一致、截图不是最终 Demo，或收件地址存在未解决冲突，固定 `FINAL LINK / RECIPIENT PATH CHECK = FAIL` 与 `NOT READY`，仅可保留 `DRAFT ONLY — NOT AUTHORIZED TO SEND`；不得以“已在发件箱”或无退信替代此检查。

## 5. 固定首封模板

```text
Subject: A website concept for [Business Name]

Hi [Name / Business Name team],

I came across [Business Name] while looking at independent businesses in [Location] and noticed [one short, factual business observation].

I’m Eli, an independent web designer. Rather than sending a generic web design pitch, I put together a small website concept specifically for [Business Name], showing one way to [clear business outcome].

You can view it here:

[DEMO URL]

I haven’t made any changes to your current website — this is simply an independent concept for you to look at.

If you like the direction, just reply to this email. I’d be happy to send you the demo’s HTML, CSS and JavaScript source files at no charge, with no obligation to hire me.

If you’d prefer me to finish and tailor it for [Business Name], I can help with that too.

Eli
Independent Web Designer
[REDACTED_EMAIL]
+86 182 6851 4405

If you’d prefer not to hear from me again, reply “unsubscribe” and I won’t contact you again.
```

Owner 姓名未知时固定使用 `Hi [Business Name] team,`，不得猜姓名。

## 6. 纯文本与 HTML

纯文本版沿用固定结构，并保留完整裸 `[DEMO URL]`。

HTML 版不得改变正文逻辑，必须使用 UTF-8、简单 HTML、可点击文字链接和默认 1 张可点击截图：

```html
<p>You can view it here:</p>
<p><a href="[DEMO URL]">View the unlisted concept preview for [Business Name]</a></p>
<p><a href="[DEMO URL]"><img src="[Demo Screenshot URL or CID]" width="600" alt="Preview of the website concept for [Business Name]"></a></p>
<p>Full link: [DEMO URL]</p>
```

- 默认 1 张图，最多 2 张；显示宽度约 600px，压缩后单张尽量 `<=300KB`，使用 HTTPS。图片被屏蔽时，文字链接、业务名 alt 与完整裸 URL 仍须表达完整。
- 图片必须是实际 Demo 截图，外层 `<a href="[DEMO URL]">` 必须可点击；不可用普通附件替代正文预览。
- 禁止脚本、复杂 CSS、远程字体、追踪像素、隐藏图片、UTM、收件人行为追踪或远程读取行为。

## 7. 标准化实验

对 20–30 个合格 Prospect 连续使用同一核心结构，只变化：Name、Business、Location、Personal observation、Business outcome、Demo URL。不得为每个客户发明不同模板。后续只按真实 `Reply Rate / Positive Reply Rate / Asked Price / Deposit` 比较；未发生结果保持空值。

## 8. 发送前 QA（13 项）

1. 是否基于证据真实个性化？
2. 是否没有批评客户网站的语气？
3. 是否明确已经做了 Demo？
4. 是否写明 `specifically for [Business Name]`？
5. 是否使用自然、简单的 Business Outcome 英语？
6. CTA 是否明确客户只需回复即可免费取得 Demo 的 HTML/CSS/JS，且没有雇佣义务？
7. 是否没有在首封写 AU$800、定金、合同或 ROI？
8. 是否按实际状态描述 Demo，且没有把 public/unlisted 称为 private/unpublished？
9. 是否含可执行 unsubscribe，HTML 文字链接和截图是否都可点击且无追踪？
10. 是否已确认 `SOURCE GIFT ELIGIBLE = YES`，且未误承诺第三方素材、账户、托管或支持？
11. 是否没有在首封直接附源码、ZIP 或陌生下载链接？
12. 是否约 100–160 词？
13. 是否完成 `FINAL LINK / RECIPIENT PATH CHECK = PASS`，并已核对最终裸 URL、文字/截图链接、当前截图和收件地址？

任一失败，先修复再输出。

### 8A. OUTREACH PRE-SEND INTERNAL-TEXT GATE

本节是每封邮件进入可发送状态前的权威内部文字 Gate。必须检查最终将发送的：Subject、纯文本、HTML 可见文字、图片 `alt/title`、附件或内嵌截图的可见内容、会向客户暴露的截图文件名、链接文字、邮件签名，以及实际点击后打开的最终 Demo 页面。必须真实打开并检查将要发送的截图与 Demo 最终版本；只搜索邮件源码、只依赖 Demo 以前的 PASS 或 Owner 自述均不够。

禁止向客户泄露 `AI-generated/generated with AI`、prompt/source/hash/rights status、`CUSTOMER AUTHORIZATION: NOT VERIFIED`、internal review/PMO、draft only/not authorized to send、placeholder/mock/TODO、素材授权、制作流程或内部风险等治理文字及同义表达。若截图或点击后的页面命中，固定：

```text
OUTREACH PRE-SEND INTERNAL-TEXT GATE: FAIL
Authorization: DRAFT ONLY — NOT AUTHORIZED TO SEND
```

不得发送。正常、自然的业务图片 alt，准确的 `Unlisted concept preview / Independent concept preview` 描述与必要退订文字允许保留；退订不是内部免责声明，不得误删。公网但不主动列出的 Demo 仍不得称 `private`。

内部 `OUTREACH DRAFT PACKAGE` 中的 Authorization、Rights status、Consent/lawful-basis 等字段必须继续保留，但只能存在于内部证据包，不得复制到客户邮件正文、截图、附件可见内容或点击后的页面。

QA 回报固定包含：

```text
CLIENT-VISIBLE INTERNAL-TEXT GATE: PASS/FAIL
OUTREACH PRE-SEND INTERNAL-TEXT GATE: PASS/FAIL/NOT RUN
FINAL LINK / RECIPIENT PATH CHECK: PASS/FAIL/NOT RUN
Scan scope:
Hits:
```

不得在回报中粘贴秘密。新 Demo、新邮件和所有未发送 Demo/草稿立即适用；已发送邮件/Demo 默认不追溯、不撤回、不补发。旧 Demo 只有再次使用、再次截图或再次外联时才重新过 Gate。即使两个 Gate 均为 PASS，发送仍须当前用户针对具体商户明确授权并通过独立合规 Gate。

## 9. 用户输出与内部证据包

首封起草完成并在内部通过 QA 后，最终对用户只返回：

```text
Subject

Email body
```

不输出长篇分析、评分或多套模板，除非用户明确要求。客户研究/PMO 的内部 `OUTREACH DRAFT PACKAGE` 仍按 PROJECT_CORE 第 13 节保留全部证据字段；这不改变首封对用户的精简输出。

## 10. 授权与澳大利亚合规 Gate

- 固定默认：`DRAFT ONLY — NOT AUTHORIZED TO SEND`。
- 模板合格、公开商业邮箱、Demo 完成或 PMO 验收，都不构成营销同意或发送许可。
- 真实发送前必须逐家独立核验邮箱来源、业务相关性、拒绝营销声明、适用同意/法律依据、真实 Sender 身份和可执行退订；本文件不是法律意见。
- 未获当前用户对具体商户明确授权，不得发送/联系、登录 Gmail、提交表单、部署、修改客户网站、付款、读取 secret 或启动自动化。
- 官方参考：[ACMA: Avoid sending spam](https://www.acma.gov.au/avoid-sending-spam)；[Spam Act 2003 — current versions](https://www.legislation.gov.au/C2004A01214/latest/versions)。

## 第一性与红队结论

- 前提：首封成功只需让合格老板打开定制 Demo 并回复；报价、审计和设计反馈会分散目标。
- 误用：批评触发防御；不同模板破坏实验；把公网称 private 造成失信；承诺不可转让的素材或把免费源码误写成完整免费交付；把公开邮箱或模板 QA 当发送许可；HTML 图片未链接导致核心 Demo 入口失效。
- 阻断证据：任一 QA 失败、Demo/链接状态不实、截图不可点击、合规或授权未证实时，状态保持不可发送。
- 残余风险：即使格式合格，仍无法证明送达、已读、回复或法律适用性。
- 闭环：固定结构实验 → 只记录真实结果 → PMO 复核；发送、合规与 Demo 状态始终独立过 Gate。
